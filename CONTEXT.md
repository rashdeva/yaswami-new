# Я с вами

> Общее понимание проекта (Дананг, RSVP, агенты) — `docs/product-vision.md`. Описание ниже — словарь прошлой версии (каталог в Грузии), пока не переписан.

Каталог практик и телесно-ориентированных событий в Грузии (Тбилиси, Батуми и выездные). Наполняется автоматически из публичных анонсов; пользователь находит событие на нужный день и уходит к организатору.

## Language

**Город** (City):
Место, где работает сервис: «Дананг». К городу относятся Source, собранное событие, организатор (а с ним и его Practice) и событие Ясвами — у каждого `city_id`. Собранное событие получает город Source, организатор — город события, по которому найден; команда может сменить. Всё, чему город не указан, — первый город (Дананг); витрина пока показывает только его.
_Avoid_: локация, регион

**Practice**:
Устойчивое предложение ведущего или площадки: что происходит, кто ведёт, какой формат. Живёт дольше одной даты. Услуга мастера без расписания (массаж, персональные тренировки, уроки) — тоже Practice, просто без Session. Сборщик извлекает Practice из самопредставления Host в чате и хранит в таблице `practices`: у каждой свой `id`, по нему на неё записываются и команда принимает решение. В интерфейсе Practice без Session называется «услуга»: вкладка «Услуги» — мастера и их Practice. «Записаться» на Practice фиксирует намерение (`practice_signups`) и уводит в чат Host; подтверждает запись сам Host. У каждой Practice свой статус модерации (`pending` → `published` или `rejected`), как у собранных событий: в каталоге видна только одобренная командой.
_Avoid_: класс, занятие, активность

**Session**:
Конкретное проведение Practice: дата, время начала, место. Многодневный ретрит — одна Session с интервалом дат. Точность места имеет три уровня: `venue` (точка на карте), `area` (город или регион, точки нет), `hidden` (место сообщают после регистрации).
_Avoid_: событие (двусмысленно), инстанс, occurrence

**Host**:
Человек или площадка, к которым уходит пользователь для записи. Владеет Practice. Название — как в Luma API. Профиль Host собирается автоматически по контакту из Announcement и его каналу; пока сам человек не вошёл в Ясвами, профиль не подтверждён. Команда может добавить Host по username: до проверки сборщиком это заготовка без Telegram id.
_Avoid_: organizer, ведущий, автор, вендор

**Source**:
Публичный канал, из которого система получает анонсы: Telegram-канал, Instagram-профиль, сайт. Канал Host, найденный в его профиле, становится Source автоматически. У Source может быть указан Host — чей это канал (ставит сборщик или команда): анонс без контакта из такого Source получает контактом этого Host.
_Avoid_: фид, аккаунт, парсер

**Announcement**:
Одна публикация из Source в исходном виде, до извлечения. Одна Announcement может породить несколько Session.
_Avoid_: пост, материал

**Card**:
То, что видит пользователь: Session вместе с данными её Practice и Host.
_Avoid_: карточка события, листинг

**Venue**:
Физическая площадка, где проходят Session: студия, баня, дом в горах. Живёт дольше любой Practice и объединяет разные Practice разных Host.
_Avoid_: локация, место, спот

**Topic**:
Тема из закрытого списка: `TOPIC_GUIDES` в `packages/core/src/topics.ts` (баня, йога, телесные практики, спорт, игры и другие). На Topic строятся фильтры и Collection; у Session их может быть несколько. Список Topic — это же и контент-политика: публикуется то, что попадает в существующий Topic, а допустимость нового вида практик решается добавлением Topic, а не отдельным фильтром.
_Avoid_: категория, рубрика, тематика

**Tag**:
Свободная метка, извлечённая из Announcement и не входящая в список Topic (кундалини, чайная церемония, звуковое путешествие). Копится для наблюдения; популярный Tag со временем становится Topic.
_Avoid_: ключевое слово, метка

**Пометка**:
Короткий ярлык на карточке ленты, который подсказывает, почему открыть именно это событие: «Через 40 мин», «Популярное», «Бесплатно». Считается из времени, цены и отклика на Announcement; сам отклик (просмотры, реакции) видит только команда.
_Avoid_: бейдж, значок

**Collection**:
Индексируемая страница-подборка: город + Topic + период («йога в Тбилиси на выходные»). Основная единица SEO; отдельная Session в поиске не индексируется.
_Avoid_: листинг, категория, фид

**Contact**:
User из аудитории Host: зашёл на его событие или ответил на него. Название — как в Luma API (contacts календаря). На Contact строятся рассылки и цепочки Host.
_Avoid_: клиент, подписчик, лид

**Возможность** (Feature):
То, что открыто не всем User: сейчас одна — `event_create`, создавать события. Включается человеку лично (команда в админке; сама — тому, кто подтвердил собранное событие как своё) или сразу всем (`FEATURES_ON`). Это право: его проверяет сервис. В Luma такого нет.
_Avoid_: роль, флаг, тариф

**Флаг**:
Переключатель в PostHog для эксперимента или постепенной выкатки: текст, вид экрана, порядок блоков. Действует только в интерфейсе и всегда имеет значение по умолчанию в коде. Прав не даёт — для этого Возможность.
_Avoid_: фича-тогл, возможность

**Visit**:
Один заход User на страницу события, с отметкой, по чьей ссылке он пришёл. В Luma такого нет — это наше.
_Avoid_: просмотр, клик, хит

**User**:
Опознанный посетитель. В v1 существует только внутри Telegram Mini App (по init-data); на сайте посетитель анонимен, а его избранное живёт в браузере.
_Avoid_: аккаунт, посетитель, клиент

**Admin action**:
Одно изменение, которое сделал кто-то из команды — в админке или агент через MCP: кто, через какой вход, каким инструментом, с чем, снимки до и после. Пишется в журнал (`admin_actions`); отменить — восстановить снимок «до». В Luma такого нет — это наше.
_Avoid_: лог, аудит-запись, история изменений

**Hidden conversation** (скрытый диалог):
Диалог, который команда убрала из «Людей» и «Ленты», потому что отвечать не собирается: спам, случайный человек. Скрытие не навсегда: следующее сообщение человека снимает его, и диалог возвращается в список. Вернуть руками — фильтр «Скрытые». Поле `hidden_at`; во входе — `is_hidden`, как у типов билетов Luma. Переписки в Luma нет — это наше.
_Avoid_: архив, бан, удалённый диалог

**Typing** (кто пишет):
Мгновенная отметка в админке, что в диалоге сейчас пишут: агент готовит ответ (видно, сколько уже написано) или человек набирает сообщение. Не хранится. «Печатает» видно только у людей на наших аккаунтах: о тех, кто пишет боту, Telegram боту не сообщает. Человек, в свою очередь, видит ответ роли поддержки по мере написания — это **живой ответ** (`sendMessageDraft`): сначала «Смотрю, что есть…», потом текст; временное превью Telegram, которое само сменяется готовым сообщением. С черновиком агента его не путать: черновик ждёт нашего «Отправить». В Luma такого нет — это наше.
_Avoid_: статус, онлайн; «черновик» — для живого ответа

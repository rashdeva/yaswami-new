# Фото и видео анонсов храним в Cloudflare R2

Сборщик забирает из публикации-источника все фото (превью 800 px) и видео до 50 МБ и кладёт их в S3-совместимый бакет Cloudflare R2 с открытым чтением. В `collected_events.announcement.media` ложится готовый открытый адрес каждого файла; API отдаёт его как есть, полем `media`.

Почему не иначе:

- **Postgres (ADR-0003)** годится для превью на десятки килобайт. Ролик весит 5–30 МБ, альбом фото — около мегабайта. ADR-0003 сам называет это поводом переезжать в бакет.
- **Storage Buckets Railway** закрыты: открытых бакетов нет, файл отдаётся только по подписанной ссылке или через наш сервер. Пришлось бы подписывать ссылки в API на каждый запрос.
- **R2**: 10 ГБ и исходящий трафик бесплатно, бакет можно открыть на чтение. API ничего не подписывает, а сборщику достаточно `PUT` по S3 (`aws4fetch`, без AWS SDK).

## Consequences

- Пишет в бакет только сборщик; ключи от него есть только у сборщика.
- В базе лежит полный адрес. Если сменится домен бакета, старые адреса придётся переписать запросом.
- Обложки, аватары и фото сообщества остаются в Postgres (ADR-0003).
- Бакет `yaswami-media` в аккаунте Cloudflare команды, токен `yaswami-collector` пишет только в него. Открытый адрес пока r2.dev: Cloudflare ограничивает его по частоте запросов и не советует для продакшена, а свой домен (`media.yaswami.com`) не подключить, потому что зона yaswami.com живёт в другом аккаунте Cloudflare. Подключить домен — тогда переписать адреса в `announcement.media` одним запросом.

# Витрину собирает ИИ-куратор из полок, команда видит и закрепляет

Витрина сейчас — один список событий по дням с фильтром по темам. По PostHog за 12–25 ноября 2026 (≈55 внешних людей) фильтр тем трогали 3 человека, поиск открывали 2, обычный путь — открыть 1–3 карточки и уйти; при этом «Услуги» и «Вакансии», разложенные по полочкам, листают охотно. Люди выбирают из готового, а не фильтруют сами.

Поэтому витрина города становится упорядоченным списком **полок** (в Luma аналога нет, имя наше). Полка — заголовок, обложка (иконка темы), набор событий и способ сборки:

- **по правилу** — «Сегодня вечером», «На выходных», «Бесплатно», «Можно без опыта»: условие на дату, цену, `beginner_friendly`, тему, популярность; события считаются при каждом запросе витрины, ИИ не нужен;
- **вручную** — список событий, который составил автор полки (команда или куратор), со сроком показа.

Полки собирает и переставляет **куратор** — новая роль Hermes в `agents/curator`, как `host`, `support` и `hunter`. Раз в день (в 7 утра по часам города задание шлёт API, `apps/api/src/curator.ts`) он смотрит события города на неделю через MCP, собирает тематические полки («Баня недели», «Где потанцевать в пятницу»), пишет названия, выбирает обложки и порядок, а по показам и открытиям полок (события `shelf_viewed`, `shelf_item_opened` в PostHog) поднимает сильные и прячет слабые. Пишет он теми же операциями, что и админка: сервис + REST + MCP, по правилу 1 из `AGENTS.md`. Своего входа в базу у куратора нет; сервис узнаёт его по токену с областью `curator`.

Команда управляет витриной в админке:

- у полки видно автора («ИИ» или «Команда») и историю с причиной, которую куратор передаёт в операцию;
- **закреплённую** полку куратор не меняет и не удаляет; правка человеком содержимого полки (название, правило, события, обложка, заметка, срок) закрепляет её сама, а смена места и статуса — нет: иначе одна перестановка закрепила бы полки куратора, которые никто не правил;
- у города есть режим: **черновик** — изменения куратора ждут «Опубликовать», **сам** — выходят сразу. Новый город начинает с черновика.

История и откат — это журнал действий команды (ADR-0004): операции полок идут через `audited`, куратор пишет от владельца своего токена, отмена — восстановление снимка.

Ограничения куратора проверяет сервис, а не промпт: в полку попадают только события из нашего каталога этого города (и соседних); полка, где меньше трёх событий, не показывается; закреплённые полки и полки команды куратору недоступны на запись, и встать выше них он не может (сервер сдвигает его полку под них); число изменений витрины в сутки ограничено, чтобы витрина не менялась у людей каждый час.

Почему не иначе:

- **Только правила, без ИИ.** Покрывают даты и цену, но не дают тематических подборок, названий и порядка под то, что происходит в городе на этой неделе; команде пришлось бы собирать их руками каждый день.
- **ИИ напрямую рисует вёрстку витрины** (отдаёт готовую разметку или свободный JSON). Команда не может закрепить или поправить отдельный кусок, сервис не может проверить ограничения, а витрина ломается от любой ошибки модели. Полки — данные с проверяемой схемой.
- **Отдельный путь записи для ИИ** (своя таблица черновиков, свой вход). Вторая система прав и истории рядом с журналом ADR-0004; правка человека и правка куратора расходились бы.
- **Персональная лента для каждого гостя (рекомендательная модель).** На десятках людей в неделю учиться не на чем. Пока личное только одно: полки тем, на которые человек подписан, поднимаются выше.

## Consequences

- Новые сущности: полка (`shelves`) и режим витрины у города (`cities.showcase_mode`); порядок — поле `position` полки, публикация — её `status`. Операции — `showcase_get` и `admin_shelves_*` в `apps/api/src/shelves.ts`, REST и MCP, тест через HTTP в `api.test.ts`; изменяющие — через `audited`. Если показать гостю нечего — своих полок нет, все предложены, сняты, истекли или полупустые, — витрина из полок по умолчанию (`DEFAULT_SHELVES`).
- В `CONTEXT.md` — термин «Полка», разведённый с Collection (индексируемая страница «город + Topic + период»).
- Новая роль `agents/curator`: токен области `curator` — каталог и инструменты полок. Аналитику полок (`shelf_viewed`, `shelf_item_opened` в PostHog) куратор пока не читает: порядок он ставит по каталогу; читать её — следующий шаг.
- `apps/web`: витрина рисует полки; полный список по дням остаётся внизу. Аналитика: `shelf_viewed`, `shelf_item_opened` с id полки и автором.
- Мокапы: холст «Я с вами — новые экраны», ряд «Витрина» (главная из полок, подборка, админка). Задача — issue #171.

## Когда пересматривать

Если куратор в режиме «сам» больше месяца не даёт лучших открытий полок, чем полки по правилам, — оставить правила и ручные полки команды, а куратора убрать. Если гостей станет достаточно для обучения — вернуться к персональному порядку полок.

# Админка (`apps/admin`)

Страница команды на `/admin`: переписка, агенты, организаторы, каталог собранных событий, события Ясвами, пользователи, источники анонсов, наши аккаунты Telegram и журнал действий команды с отменой. Всё, что команда может сделать в сервисе (`/admin/*`), делается и правится здесь. Что она делает и зачем — `docs/agents-inbox.md`.

React 19 + Vite, отдельное приложение (`@yaswami/admin`) на том же домене. Адреса — TanStack Router (`basepath: '/admin'`), данные с сервера — TanStack Query; другого менеджера состояния нет. Оформление — shadcn/ui на Tailwind v4. Правило то же, что во фронте: **компонент рисует, хук знает, функция считает.**

**shadcn/ui и Tailwind живут только в `apps/admin`; мини-приложение и сайт (`apps/web`) их не используют: там свои компоненты и `tokens.css`.**

## Где что лежит

```
src/
  api.ts            единственное место, где есть fetch: только админские методы; типы — из @yaswami/core; MESSAGES — тексты ошибок
  main.tsx          вход: QueryClient, тема по prefers-color-scheme, тосты, русские тексты ошибок zod
  router.tsx        все маршруты кодом и страницы: страница берёт адрес (параметры, фильтры) и раздаёт экрану props
  App.tsx           корневой layout: вход и «нет доступа», боковое меню, шапка
  hooks/            useXxx.ts по ресурсам: useQuery/useMutation поверх api.*; клавиши переписки
  hooks/keys.ts     все ключи запросов
  hooks/useAct.ts   действие админа: тост при ошибке, тост «Отменить» после отменяемого, после — перечитать данные; useUndo
  screens/          раздел или карточка = композиция: данные из хуков, разметка из components/; про адреса не знает
  components/       свои составные части: Page/Section/Hint/Loading/Nothing, Fields (поля форм), Confirm, History,
                    EntityLink (все ссылки), Search, Cover, UserPicker, EventFields; чат: Thread, Reply, Draft
  components/ui/    компоненты shadcn — ставит CLI, руками не правятся
  lib/              чистые функции без React, CSS и import.meta.env: переписка, журнал (подписи, разница снимков), каталог, формы
  index.css         тема shadcn (переменные, светлая и тёмная) и свои анимации
```

Разделы и адреса (все под `/admin`):

| Раздел | Адрес | Что там |
|---|---|---|
| Люди | `/?c=<диалог>&agent=<роль>` | переписка по людям |
| Лента | `/feed` | ждут вас + живой поток |
| Организаторы | `/hosts?q=`, `/hosts/$id` | профили, их события в каталоге, переход в диалог |
| Агенты | `/agents` | роли Hermes и их счётчики |
| Каталог | `/catalog?status=&q=`, `/catalog/$id` | собранные события: модерация, поля анонса, обложка, ролик (заказать, перерисовать), записавшиеся; `status=covers` — ждут обложки; `status=queue` — «По одному»: ждущие решения очередью, слева текст анонса, справа поля, «Сохранить и одобрить» одним действием |
| События Ясвами | `/events?when=&q=`, `/events/new`, `/events/$id` | события сервиса: поля, типы билетов, гости, отзывы |
| Пользователи | `/users?q=`, `/users/$id` | поля, события и ответы, аудитория, токены, удаление; ссылка на его действия в PostHog |
| Источники | `/sources` | каналы и группы, откуда сборщик берёт анонсы: добавить, выключить или включить |
| Аккаунты | `/accounts` | наши аккаунты Telegram: вход, переименование |
| Журнал | `/actions?entity=&action=&actor=`, `/actions/$id` | действия команды, разница снимков, отмена |

До этого `/events` был модерацией собранных событий; теперь она в «Каталоге», а `/events` — события Ясвами.

## Правила

- **Запросы — только в хуках.** `api.*` видят только файлы в `hooks/`. Загрузка — `useQuery` с ключом из `hooks/keys.ts`, изменение — `useAct(…)`: он показывает ошибку тостом и перечитывает все запросы — запись, списки и журнал (данных в админке немного). Полный ответ сервера кладётся в кэш карточки в `onSuccess` хука.
- **Опрос — `refetchInterval`**, а не таймеры: лента и открытая переписка — раз в 4 с, каталог — раз в 30 с; карточки не опрашиваются, их перечитывает `useAct` после действия.
- **Вход** — cookie сайта (`/api/auth/telegram/login`), в разработке — `Bearer VITE_DEV_TOKEN` (токен админа из `pnpm api:token`). Telegram initData здесь нет. Экраны рисуются только после загрузки ленты: до неё `App.tsx` показывает вход, «нет доступа» или ожидание.
- **Типы запросов и ответов — из `@yaswami/core`**, по сети — `Wire<T>`. Новая операция админки — строка в `api.ts` с тем же именем, что у сервиса, и хук в `hooks/`.
- **Текст ошибки для человека** — в `MESSAGES` в `api.ts`, по коду ошибки бэка.
- **Чистая функция — в `lib/`, с тестом рядом** (`*.test.ts`, `node:test`). Файлы `lib/` запускает Node напрямую: импорты относительные, с расширением `.ts`, без алиаса `@/`.
- **Разметка — только компоненты shadcn; `className` — только раскладка.** Есть компонент — сырой тег не пишем: список строк — `item`, ключ-значение — `table`, вкладки и отбор — `tabs`/`toggle-group`, предупреждение — `alert`, состояние — варианты `badge`, картинка с пропорцией — `aspect-ratio`, прокрутка — `scroll-area`, клавиша — `kbd`, разделитель в ленте — `marker`. В экранах классы задают только раскладку: `flex`, `grid`, `gap`, `col-span`, ширину и высоту, `truncate`, `overflow`. Размер шрифта, цвет и толщина — в компонентах shadcn или в наших обёртках, по одному месту на вид:
  - `Page` (`title`, `description`) и `Section` (`description` — `CardDescription`) — заголовки и пояснения;
  - `Hint` — мелкая подсказка или «пусто» внутри блока;
  - `EntityLink`, `ActionLink`, `ExternalLink`, `TelegramLink` — все ссылки;
  - `Search` — поле поиска, `Cover` — обложка 9:16.

  Цвета — только переменные темы и варианты компонентов, без `green-600`, `amber-…` и произвольных значений вида `text-[11px]`. Своего CSS нет, кроме палитры и анимаций в `index.css`.
- **Адрес — в `router.tsx`.** Экран получает выбранное, фильтры и обработчики через props; фильтры и поиск живут в search params, переходы после действия (создали → карточка, удалили → список) делает страница. Ссылки на карточки сущностей — `components/EntityLink.tsx` (через `entityLink` в `lib/journal.ts`): второе и последнее место, где известны адреса.
- **Формы — react-hook-form + `zodResolver` со схемой из core.** Значения формы — в форме API (null, ISO, массивы); поля из `components/Fields.tsx` переводят их для ввода и обратно. Сохранение — `saveDirty(form, hook.update)`: шлём только изменённые поля, ошибки `invalid_input` встают у полей (`showIssues`).
- **Удаление, неотменяемое и платное (заказ ролика, перерисовка обложки и ролика) — через `Confirm`** (AlertDialog): в тексте сказать, что случится; у отменяемого удаления — `UNDO_HINT` («можно отменить в журнале»). `alert()`/`confirm()` не используются.
- **Пустое и загрузка:** `Loading` (скелетон), `Nothing` (пустое состояние), `Failed` (ошибка карточки) из `components/Page.tsx`; списки — таблицы shadcn.
- **Переписка — компоненты чата shadcn**: `message-scroller`, `message`, `bubble`, дни разделяет `marker` (`components/Thread.tsx`); поле ответа и черновик — `input-group` (`Reply.tsx`, `Draft.tsx`); список людей — `item` с `avatar`, фильтры — `toggle-group`; клавиши в подсказках — `kbd`.
- **Клавиши** — `hooks/useInboxKeys.ts`; поле находят по `data-reply`, `data-draft`, `data-search`, выбранную строку — по `data-selected`.

## Журнал и отмена в интерфейсе

Журнал команды — ADR-0004 и `docs/agents/api.md`. В админке:

- **Тост «Отменить».** У отменяемого действия в хуке указано `useAct(fn, { undo: (input, result) => [entity, entity_id] })`. После успеха `useAct` берёт последнюю строку журнала по этой сущности от текущего админа (`GET /admin/actions?entity&entity_id&actor_id&pagination_limit=1`) и показывает тост с кнопкой; отмена показывает тост «Вернуть» (отмена отмены). Неотменяемые (отправка, удаление аккаунта, вход, отзыв токенов, заказ ролика) — без `undo` и через `Confirm`.
- **«История»** — `components/History.tsx`: последние действия над сущностью (`entity` + `entity_id`) в её карточке, с кнопкой отмены.
- **«Журнал»** — лента с подгрузкой по `next_cursor` и фильтрами; карточка действия — разница полей `row` и сводка по детям (`snapshotDiff`), сырые снимки — свёрнуты.
- Подпись нового действия — строка в `ACTIONS` в `lib/journal.ts`; новая сущность — в `ENTITIES`, `entityLink`, а её дети — в `CHILDREN`.

## Новая сущность в админке

1. Методы в `api.ts` (тем же именем, что у операции), тексты новых ошибок — в `MESSAGES`.
2. Ключи в `hooks/keys.ts`, хук `hooks/useXxx.ts`: `useXxx(id)` на `useQuery`, `useXxxActions(id)` на `useAct` с `undo` для отменяемых.
3. Экраны `screens/XxxsScreen.tsx` (список: таблица, поиск из props) и `screens/XxxScreen.tsx` (карточка: `Section` с формой, `Confirm` на удаление, `History`).
4. Маршруты и страницы в `router.tsx`, пункт меню в нужную группу `NAV` в `App.tsx`, ссылка в `entityLink` и подписи в `lib/journal.ts` (с тестом).

## Компонент shadcn

```
cd apps/admin
pnpm dlx shadcn@latest search @shadcn -q <слово>   # есть ли такой
pnpm dlx shadcn@latest add <имя>                    # кладёт в src/components/ui, ставит зависимости
```

Настройки — `components.json` (стиль `radix-nova`, нейтральная палитра, иконки lucide, алиас `@/*`). Файл в `components/ui/` не правится: нужен другой вид — `className` снаружи или своя обёртка в `components/`. Компонент, который перестал использоваться, удаляется.

## Запуск и проверка

`pnpm dev` (API на 3000) и `pnpm dev:admin` — админка на `http://localhost:5174/admin/`, запросы `/api` уходят на локальный API; превью `admin` в `.claude/launch.json`. Сборка — `pnpm build:admin`: сервер отдаёт `apps/admin/dist` по `/admin` (`apps/api/src/main.ts`), в образ её кладёт стадия `admin` в `Dockerfile`.

`pnpm typecheck`, `pnpm test`; затем открыть раздел в превью и пройти сценарий руками.

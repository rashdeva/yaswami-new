# Агенты (Hermes)

Роли и скиллы агентов «Я с вами». Как это устроено и зачем — `docs/agents-inbox.md`.

```
agents/
  Dockerfile        образ сервиса hermes: официальный Hermes + файлы ролей
  init.sh           при старте контейнера кладёт роль на том /opt/data
  operator/         роль: собеседник команды в Telegram (профиль Hermes по умолчанию)
    SOUL.md         характер и правила
    config.yaml     модель, инструменты, подключение к нашему MCP
    skills/         скиллы роли (SKILL.md)
  support/          роль: отвечает людям, которые пишут боту «Я с вами» (профиль support)
  hunter/           роль: пишет черновики ответов на вопросы «куда сходить» в чатах (профиль hunter)
  host/             роль: пишет черновики сообщений организаторам (профиль host)
  illustrator/      роль: рисует обложку в фирменном стиле и ролик-историю с неё через Grok Imagine (профиль illustrator)
```

## Выкладка

Сервис `hermes` в проекте Railway `yaswami`, том на `/opt/data` (память, сессии, вход в модель).

```bash
railway up agents --path-as-root --service hermes
```

Роль меняется правкой файлов здесь и повторной выкладкой: при старте `init.sh` перезаписывает `SOUL.md`, `config.yaml` и `skills/yaswami` каждого профиля на томе.

Один процесс Hermes обслуживает оба профиля на порту 8642: `operator` — по `/v1`, `support` — по `/p/support/v1`, у каждого свой ключ. Наш API ходит к `support` по внутренней сети Railway (`http://hermes.railway.internal:8642/p/support`); сеть эта только IPv6, поэтому `API_SERVER_HOST=::`. Остальное на томе (память, вход в Grok, расписания) сохраняется.

## Переменные сервиса

| Переменная | Что это |
|---|---|
| `YASWAMI_MCP_URL` | адрес MCP нашего API: `https://<сайт>/mcp` |
| `YASWAMI_MCP_TOKEN` | токен `ysw_…` пользователя из `ADMIN_IDS`: от его имени оператор читает переписку и пишет людям |
| `YASWAMI_SUPPORT_MCP_TOKEN` | токен роли support с областью действия: `pnpm api:token <telegram id> <имя> support`. Сервер отдаёт ему только каталог и `person_*`, REST закрыт. Не задан — роль работает на токене админа (при старте пишется предупреждение) |
| `YASWAMI_CATALOG_MCP_TOKEN` | токен роли hunter: `pnpm api:token <telegram id> <имя> catalog` — только каталог |
| `TELEGRAM_BOT_TOKEN` | токен бота командного чата (отдельный от бота «Я с вами») |
| `TELEGRAM_ALLOWED_USERS` | Telegram id тех, с кем бот разговаривает, через запятую |
| `API_SERVER_ENABLED`, `API_SERVER_HOST`, `API_SERVER_KEY` | HTTP-вход Hermes: `true`, `::` и ключ роли `operator`; ключ не короче 16 символов, иначе вход молча не включается |
| `SUPPORT_API_KEY` | ключ роли `support`; тот же ключ — в `SUPPORT_KEY` сервиса `api` |
| `HUNTER_API_KEY` | ключ роли `hunter`; тот же ключ — в `HUNTER_KEY` сервиса `api` |
| `HOST_API_KEY` | ключ роли `host`; тот же ключ — в `HOST_KEY` сервиса `api`. Не задан — роль не ставится |
| `ILLUSTRATOR_API_KEY` | ключ роли `illustrator`; тот же ключ — в `ILLUSTRATOR_KEY` сервиса `api`. Не задан — роль не ставится |

## Вход в модель

Хранится на томе. Основная модель — ChatGPT по подписке (`openai-codex`) у `operator`, `support`, `hunter` и `host`; запасная у них и единственная у `illustrator` — Grok по подписке (`xai-oauth`).

В ChatGPT входим **один раз, в основной профиль**: профиль без своего входа берёт его оттуда. Свой вход в профиле ломает всё — OpenAI держит одну живую сессию на аккаунт и при новом входе отзывает прежнюю.

```bash
railway ssh --service hermes -- hermes auth add openai-codex --no-browser
```

Grok, наоборот, входит в каждый профиль отдельно:

```bash
railway ssh --service hermes -- hermes -p illustrator auth add xai-oauth --no-browser
```

Команда печатает адрес и код; код подтверждается в браузере под аккаунтом с подпиской.

## Обложки и ролики (illustrator)

Обложка — чистая живая фотография во весь кадр 9:16, без текста и графики: фото организатора с убранными надписями или сцена, придуманная по описанию. Знак «Я с вами» поверх обложки ставит сама страница (`apps/web/public/mark.svg`), в картинку его не рисуем. Люди в придуманных сценах и роликах — разные: возраст, внешность, одежда; аудитория — русскоязычные экспаты, поэтому не все азиаты.

Обложку и ролик получают события, одобренные в админке (раздел «Каталог»): API при одобрении и дальше раз в 15 минут берёт следующее — сначала одобренные, потом уже опубликованные без ролика (`requestNextVideo` в `apps/api/src/services.ts`). Одобренное выходит в ленту, когда обработка закончилась; если она не удалась за две попытки или дневной лимит выбран — выходит как есть. Вне очереди ролик может заказать оператор инструментом `admin_videos_request` — по просьбе команды в чате. Перерисовать обложку и ролик заново — кнопка в карточке события в «Каталоге» или `admin_collected_events_redo`: обложка удаляется, обработка сбрасывается, очередь возьмёт событие минут через 20, когда сборщик вернёт фото анонса. Наш API передаёт роли данные события и фото анонса (`apps/api/src/services.ts`, `requestCollectedVideo`), роль одним вызовом `image_generate` делает обложку 9:16 (с фото анонса или, если его нет, по описанию), затем придумывает историю из пяти планов и одним вызовом `video_generate` снимает ролик на 10 секунд, первый кадр которого — эта обложка. В ответ отдаёт две ссылки. Обложку API скачивает к себе и ставит вместо фото анонса; ролик лежит в хранилище xAI, в событии хранится только ссылка, страница события играет его в шапке и сама пишет поверх название и время.

Картинки рисует ChatGPT (`image_gen: openai-codex`, подписка из основного профиля): файл остаётся в контейнере, роль отвечает `cover: MEDIA:<путь>`, а Hermes в ответе API заменяет это на саму картинку (data URL) — её и сохраняет наш API (`coverBytes` в `apps/api/src/services.ts`). Ролики по-прежнему снимает Grok Imagine по входу профиля `illustrator`; кончилась подписка Grok — роликов нет, обложки есть.

События «Я с вами» тоже получают обложку: событие создано без своей (в мини-приложении или через поддержку в чате) — API заказывает роли «только обложку» (`requestEventCover`), и через минуту-другую она появляется на странице события.

Каждая генерация стоит 1–2 доллара, поэтому: один ролик на событие (неудачная попытка тоже считается — заново не заказываем) и не больше `ILLUSTRATOR_DAILY_LIMIT` (по умолчанию 3) заказов в сутки на стороне API.

Чтобы включить: задать `ILLUSTRATOR_API_KEY` сервису `hermes`, `ILLUSTRATOR_URL` (`http://hermes.railway.internal:8642/p/illustrator`) и `ILLUSTRATOR_KEY` сервису `api`, войти в модель:

```bash
railway ssh --service hermes -- hermes -p illustrator auth add xai-oauth --no-browser
```

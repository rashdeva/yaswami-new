# Я с вами (yaswami)

События и RSVP в Telegram: мини-приложение и сайт, бот, витрина событий города, собранных из анонсов, и агенты (Hermes), которые ведут переписку. Образец продукта и API — Luma. Что и зачем строим — `docs/product-vision.md`.

## Карта

Одна операция проходит сверху вниз; каждый слой знает только о тех, что ниже.

| Где | Что там | Чего там нет |
|---|---|---|
| `apps/web` | React: экраны, компоненты, хуки | правил домена, своих типов запросов и ответов |
| `apps/api/src/app.ts`, `mcp.ts` | два тонких входа: REST и MCP | запросов к базе, правил |
| `apps/api/src/services.ts`, `inbox.ts` и соседи | операции: правила доступа, запись, побочные действия | знания о том, кто вызвал — REST или MCP |
| `packages/core` | схемы zod, типы, чистые правила (RSVP, темы) | базы, Telegram, сети |
| `packages/extract` | разбор анонса в событие через ИИ | базы |
| `apps/collector` | юзербот MTProto: читает каналы, шлёт с наших аккаунтов | правил домена: только `/internal/*` нашего API |
| `agents/` | роли Hermes; работают через наш MCP | прямого доступа к базе и Telegram |

## Правила, которые действуют всегда

1. **Операция = сервис + REST + MCP.** Новая операция — это функция в сервисах, маршрут в `app.ts` и инструмент в `mcp.ts`, все три в одном PR, на одной схеме из `packages/core`. Исключения перечислены в `docs/agents/api.md`; новое исключение добавляется туда же с причиной.
2. **Имена — как в Luma.** Перед тем как назвать ресурс, поле, путь или инструмент, найди аналог в `docs/reference/luma/` и возьми имя оттуда. Аналога нет — имя наше, и в комментарии у типа сказано, что в Luma такого нет.
3. **Логика отдельно от UI.** Компонент рисует и зовёт хук; данные, запросы и правила живут в хуках и чистых функциях.
4. **Слова — из `CONTEXT.md`.** Термин домена пишется так, как он там определён, в коде, тестах и текстах.
5. **Проверка перед «готово»:** `pnpm typecheck` и `pnpm test` (нужен `pnpm db:up`) проходят; на новую операцию есть тест через HTTP в `apps/api/src/api.test.ts`.

## Что читать под задачу

- Меняешь API, MCP, сервисы, схему базы → `docs/agents/api.md`
- Меняешь `apps/web` → `docs/agents/frontend.md`
- Называешь что-то или сверяешься с Luma → `docs/reference/luma/`
- Трогаешь переписку, админку, роли Hermes → `docs/agents-inbox.md`, `agents/README.md`
- Сбор анонсов, юзербот → `apps/collector/README.md`, `docs/adr/0001-strategiya-sbora-dannykh.md`
- Выкладка, Railway → `docs/adr/0002-railway-kak-edinaya-platforma.md`
- Исследуешь домен, пишешь термин или ADR → `docs/agents/domain.md`
- Задачи и метки (GitHub Issues `rashdeva/yaswami-new`, через `gh`) → `docs/agents/issue-tracker.md`, `docs/agents/triage-labels.md`
- Маркетинг и тексты → `docs/marketing-strategy.md`

## База знаний растёт вместе с кодом

Знание кладётся туда, где его будут искать, в том же PR, что и код. У каждого знания одно место; остальные на него ссылаются.

| Что появилось | Куда |
|---|---|
| Новый термин или уточнение старого | `CONTEXT.md` |
| Решение, которое трудно отменить, и почему отвергли другие варианты | новый ADR в `docs/adr/` |
| Правило, как писать код | `docs/agents/api.md` или `docs/agents/frontend.md` |
| Факты о чужой системе, проверенные по первоисточнику, с датой сверки | `docs/research/` |
| Чужая спецификация целиком | `docs/reference/<система>/`, файлы как скачаны |
| Замысел на будущее, который ещё не делаем | issue с меткой `needs-triage` |
| Почему строка кода такая | комментарий у этой строки |

Правило сюда, в `AGENTS.md`, попадает, только если оно нужно в любой задаче; остальное — в документ под задачу и строкой-указателем выше. Документ, который разошёлся с кодом, правится или удаляется в том же PR: `docs/architecture-draft.md` и `docs/plan.md` — черновики прошлых этапов, при расхождении прав код.
